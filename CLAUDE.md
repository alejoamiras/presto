# Presto

## Current State

- **Repo**: `alejoamiras/presto` (GitHub)
- **SDK** (`/packages/sdk`): TypeScript package `@alejoamiras/presto` — PrestoProver for native proving via localhost bb binary. Extends `BBLazyPrivateKernelProver`, auto-detects the presto, and falls back to WASM if unavailable. Browser page/Worker instances are HTTPS-only for private proving by default; an HTTPS connection failure may trigger one bounded, witness-free HTTP health diagnosis but never automatic HTTP `/prove`. Node/Bun/SSR retain the dual HTTP/HTTPS compatibility path. `PRESTO_HTTPS_ONLY` overrides the runtime default. The transport lives in core (below): `PrestoProver` is a thin adapter over `PrestoClient` (`scheme: chonk`, msgpack body, `decodeChonkProof`).
- **SDK Core** (`/packages/sdk-core`): `@alejoamiras/presto-core` — the transport and policy every adapter shares, no `@aztec/*` dependency, plain semver from its manifest (1.0.1). `PrestoClient({presto?, aztecVersion?, onPhase?})` with `checkStatus()` (10 s cache, single-flight) and `prove(request) → {kind: "native", body, durationMs} | {kind: "fallback", reason, phase?}`; the request path must be a plain absolute route path and is snapshotted before use; a route's `scheme` is checked against `/health.schemes` (absent ⇒ `chonk` only) before anything is sent; `404 → route-missing`. `PrestoStatus` carries `schemes?` and (detailed tier) `versions?`. Both SDKs depend on it at an exact version (`workspace:*` in tree, pinned at pack time).
- **SDK Noir** (`/packages/sdk-noir`): `@alejoamiras/presto-noir` (1.0.1) — `PrestoUltraHonkBackend(acirBytecode, api | () => Promise<api>, options)`, a compile-checked drop-in for bb.js's `UltraHonkBackend` public methods: `generateProof` goes to `POST /prove/ultra-honk` and falls back to the real WASM backend (`fallback: "wasm"`) or throws `PrestoUnavailableError(reason, phase)` (`fallback: "none"`); every other method delegates to WASM so verification stays circuit-bound. Structural validation of the native response (non-empty 32-byte-aligned proof, 1..64 KiB key). Exact peer `@aztec/bb.js@5.2.0`; `TESTED_BB_VERSIONS` gates `bbVersion` (`allowUntestedBbVersion` opts out); `update-aztec-version.ts` moves the peer pin in lockstep. Suites outside the unit chain: `test:identity` (bb.js `WasmWorker` reproduces `fixtures/noir/*` byte for byte) and `test:e2e` (live presto, `fallback: "none"`; `PRESTO_URL` required unless `PRESTO_NOIR_SKIP_LIVE=1`; optional `PRESTO_NOIR_W_FIXTURE_DIR` cross-check).
- **Presto** (`/packages/presto`): Tauri desktop app (macOS + Linux + Windows) — executable named `Presto` (renamed at the CARGO layer, `[[bin]]` + `default-run`, so plain-cargo and tauri builds agree; `productName`/identifier/install dir unchanged; `tauri-identity.test.ts` pins the tuple and `bundle.publisher` stays absent until it ships with an NSIS registry-migration story), system tray, multi-version bb cache, **HTTPS default-on** consented via a first-run onboarding wizard (Encrypted Connection / Start-on-Login / Auto-Update), crash recovery, site authorization (MetaMask-style origin approval, **deny-by-default**; **desktop prompts-once for localhost, headless auto-approves it**; `url::Url`-based canonicalization at server ingress + curated verified-sites registry rendering friendly name + ✓ in the popup; see `VERIFIED_SITES.md`), a **loopback `Host`-allowlist guard at ingress** (anti-DNS-rebinding; exact host+port, both HTTP/HTTPS listeners), **Origin-tiered `/health`** (minimal body for unapproved origins), Settings window, speed control, signed auto-update (Ed25519 via tauri-plugin-updater, with a pre-flight artifact size cap). **Cross-OS browser trust** (`src-tauri/src/trust/`): keyless local CA (name-constrained to loopback) installed into the macOS Keychain / Windows CurrentUser Root / Linux user NSS DBs (`certutil`, no root); rename `safari_support`→`https_enabled`; renewal consent window (macOS/Windows) vs silent rotation (Linux); NSIS uninstall hook (`$UpdateMode`-guarded). Headless server (`/packages/presto/server`) is deny-by-default with `ALLOWED_ORIGINS` / `--allow-all` opt-in, and stays TLS-free; `PRESTO_HOME` gives one instance private `config.json` / `versions/` / `data/`, and `--port <n>` is accepted only with it. **`POST /prove/ultra-honk`** (ships in 1.1.0) proves any Noir circuit with bb's `ultra_honk` scheme: JSON + base64 `{bytecode, witness, verifier_target, vk?}` → `{proof, public_inputs, vk?}` (the key is returned only when bb computed it), decoded-size caps, per-origin cap of 4 on top of the global inflight cap (429 `origin_queue_full`), same admission as `/prove` plus a revocation re-check (an Allow older than a Settings removal is dropped); on both routes an abandoned or timed-out request keeps its admission seats until the killed bb is reaped (`bb::run_bb` cancel + confirmed reap, `server::prove::on_task`); `x-aztec-version` downloads are budgeted (`versions::DownloadBudget`: 3 per origin and 6 overall per 10 min, one at a time, `429 download_budget_exhausted`), the release digest is fetched before the tarball, and only a proof that reaches bb refreshes a cached version's activity mark; `/health` advertises `schemes` on every body and `versions` (`aztec_version` → `bb_version`) on the detailed one; `api_version` stays 1. bb 5.2.0 lists but refuses the `starknet` targets (surfaced as `prove_failed`).
- **Playground** (`/packages/playground`): Vite + vanilla TS frontend — local WASM vs accelerated mode comparison, embedded wallet, ASCII animation, and a **Prove Noir Circuit** panel (`src/noir.ts`: the committed `hashchain` fixture (1,024 chained Pedersen hashes, about 10 s in WASM and 2 s natively; `square` stays the fast fixture for tests) through `PrestoUltraHonkBackend`, WASM or native, byte-checked against the committed proof; the fixture reaches the page via the `virtual:noir-fixture` Vite plugin because the dev server treats bb's extension-less outputs as JS and inflates `.gz`; `?noirStub=true` is a test-only stub WASM source for the mocked e2e; `resolve.dedupe` keeps one `@aztec/bb.js`). Deployed at `playground.presto.build`.
- **Landing** (`/packages/landing`): Static landing page at `presto.build`.
- **Banners** (`/packages/banners`): `@alejoamiras/presto-banners` — zero-dependency `<presto-banner>` web component (Shadow DOM, landing tokens/type/motion) that integrating dApps drop in to ask users to install Presto. Six variants (ribbon, billboard, dock, card, tile, sheet), state keyed to the SDK's `PrestoStatus` via `stateFromStatus` (structural `PrestoStatusLike`, no SDK dependency; the assignability is pinned in `status.test.ts`). Renders nothing until `state` is set (Tile excepted); `secure-connection-unavailable`+`unconfirmed` maps to the install pitch (that is what an uninstalled Presto looks like under browser HTTPS-only); `available` plays the detected morph then hides; the Sheet is a native modal `<dialog>`; dismissals persist per variant+state (7 days, or forever from the Sheet). `bun run dev` serves a demo page. Published as the fourth descriptor entry (`presto-banners`, manifest-versioned, 1.0.0): the publish rewrite maps every source `exports` subpath (`.` and `./register`) to its dist pair and drops `devDependencies`; its consumer profile loads both entries in Node. The playground's install strip is `<presto-banner variant="ribbon">` driven by its own view model (install pitch only; the page keeps its warn-state panels).
- **Build system**: Bun workspaces (`packages/sdk-core`, `packages/sdk`, `packages/sdk-noir`, `packages/banners`, `packages/presto`, `packages/playground`, `packages/landing`, `packages/release-feed`)
- **Linting/Formatting**: Biome (lint + format), shellcheck, actionlint, sort-package-json, cargo fmt (Rust)
- **Commit hygiene**: Husky + lint-staged + commitlint (conventional commits)
- **CI**: GitHub Actions (required PR gates: `presto.yml`, `sdk.yml`, `sdk-core.yml`, `sdk-noir.yml`, `app.yml`, `actionlint.yml`; `banners.yml` gates `packages/banners` and the SDK's `types.ts` through the same reusable; presto jobs use the central `.github/filters/presto.yml` routing contract; dependency audits are PR-path-filtered but remain unconditional for schedules, manual runs, and release calls; PR Rust caches are restore-only). The four TS package gates call the reusable `_ts-package-ci.yml` (inputs `package`, `e2e_presto`, `identity`, `live`: lint, typecheck, unit tests, packed-tarball consumer install with `scripts/sdk-tarball-consumer.sh`, and per package the sandbox e2e, the bb.js byte-identity job, or the live headless-presto job); `sdk.yml`'s dispatch takes a `package` choice. `release-sdk.yml` takes `packages` (`presto` | `presto-core` | `presto-noir` | `presto-banners` | `all`) and publishes core → noir → presto, and banners independently, through `_publish-npm.yml` (manifest-versioned siblings publish once and are reused when unchanged); `noir-gates` (identity + live at the release SHA) blocks `publish-noir`, which blocks `publish-presto`. Reusable workflows include `_e2e.yml`, `_e2e-app.yml`, `_e2e-webdriver.yml`, and the macOS/Linux/Windows updater smokes, which use the greatest complete published lower same-key baseline (including prereleases) and fail closed if none exists. `release-presto.yml` has no evergreen key-rotation override; any future key migration requires a reviewed workflow change. `smoke-updater-windows.yml` remains the secretless ephemeral L8 barrier smoke.
- **Testing**: 25 WebDriver E2E tests (macOS + Linux + Windows) via `tauri-plugin-webdriver` + WebdriverIO (incl. a real native UltraHonk proof of the committed Noir fixture), 66 Playwright UI mock tests, 18 playground Playwright mocked tests (incl. 5 Noir, network-free) plus a real-WASM Noir proof of the production bundle in the production-smoke lane, ~450 Rust tests (440 non-ignored on Linux; plus `win_acl` inline DACL tests on the windows-build lane), ~640 TS unit tests (sdk-core 189 + SDK 20 + sdk-noir 38 + banners 29 + playground 76 + presto scripts 105 + root scripts 197 + release-feed 4), sdk-noir's `test:identity` (3) and live `test:e2e` (5) in their CI lanes, plus `#[ignore]`d integration suites run in dedicated CI lanes (`trust_*`, `autostart_heal`, `uninstall_ownership` per OS; `ultra_honk_real_bb` with the real bb, followed by an HTTP smoke against two coexisting headless instances). Noir fixtures live in `fixtures/noir/` (bb.js WASM references; `scripts/noir-fixture.ts --verify`). WebDriver tests run as PR gate and pre-release gate.
- **TypeScript**: 7.0 with ES2025 target. Biome for lint/format. Rust is pinned to 1.98.0 via `rust-toolchain.toml` (CI and local); `reqwest` uses rustls + `aws-lc-rs`, so native builds need CMake.
- **Release pipeline (B6 publish/promote split)**: two dispatches. `mode=publish` (default) runs `validate → e2e-webdriver gate → build (3 Tauri + 4 headless platforms) → smoke → tag → sign-update-feed (stable) → release` and publishes the GitHub release **without touching the live feed** — stable is `--latest=false`, with the signed `latest.json` shipped as a release asset. A separate `mode=promote-only` dispatch re-verifies the published release (published/non-draft/non-prerelease, full asset set, production Ed25519 verifier over the release's own feed) then flips the KV-backed `latest.json` (`promote → verify-live-feed → bump-source` on organic GA). `promote-only <prev>` is the rollback lever; `dry_run` runs the pre-flight with no feed write. Prerelease `X.Y.Z-rc.N` publishes as a public prerelease and is never promoted. **Append-only**: no release/tag deletion (fix-forward on a colliding tag). The landing download version is derived from the signed feed, not the GitHub Latest badge.
- **Hosting**: Cloudflare Workers Static Assets serves the landing and playground; a narrowly scoped Worker reads the signed updater feed from KV. Wrangler configuration lives with each package.

## Quick Start

```bash
bun install              # Install dependencies
bun run test             # Full checks (lint + typecheck + unit tests)
bun run lint             # Linting only (biome + pkg + rust)
bun run lint:actions     # Lint GitHub Actions workflows
bun run lint:fix         # Auto-fix lint/format issues
bun run --cwd packages/sdk-core build     # Build the shared core
bun run --cwd packages/sdk build          # Build the Aztec SDK
bun run --cwd packages/sdk-noir build     # Build the Noir SDK
bun run --cwd packages/playground dev     # Playground (default)
bun run --cwd packages/playground dev:localhost  # Playground -> localhost
bun run --cwd packages/playground dev:testnet    # Playground -> testnet
```

## Development Principles

1. **Iterative implementation**: Break into small, testable steps
2. **Research first**: Understand the current system before changing it
3. **Test at each step**: Verify before moving on
4. **Prefer Bun native APIs**: Use Bun APIs over Node.js compat or third-party packages

## Workflow

Before writing any code:
1. Read relevant source files and existing tests
2. Create a task list breaking work into incremental steps
3. Work through the list one step at a time, validating after each

### Validation

- **Code changes**: `bun run lint` and `bun run test`
- **Platform-gated Rust** (`#[cfg(windows)]` / `target_os` branches): also
  `cargo check --target x86_64-pc-windows-gnu --lib` from `src-tauri` (`rustup target add x86_64-pc-windows-gnu` once for the pinned toolchain) — Linux-only checks cannot see
  a Windows compile break (twice bitten: a `pub(crate)` visibility error, and a `cfg` attribute
  detached from its function). Needs a one-off empty, gitignored
  `binaries/bb-x86_64-pc-windows-gnu.exe` placeholder for tauri-build's sidecar check; ~5s
  incremental. Clippy warnings on that target are test-only noise (CI's clippy gate is ubuntu-only).
- **Workflow changes**: `bun run lint:actions`
- **New tests**: Run the specific test file first
- **Before pushing**: Run full `bun run test` + `bun run lint:actions`
